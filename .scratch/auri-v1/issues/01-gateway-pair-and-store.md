# 01: 网关：配对并入库

**What to build:** 用户在电脑上用一条命令启动 Gateway，再用一条命令生成配对码。设备用配对码换到设备令牌，然后提交一个 Revision 并得到入库结果。这是网关的第一条完整路径，同时建立数据库迁移底座和黑盒测试框架。本工单先在本机回环地址上用明文跑通，局域网传输在工单 06。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 命令行能启动 Gateway，数据保存在指定的持久化目录，重启后数据仍在
- [ ] 命令行生成的配对码一次性、短时有效；用过或过期的配对码换不到令牌
- [ ] 设备令牌只在兑换响应里出现一次，库内只存哈希
- [ ] 带有效设备令牌提交 Revision 后返回入库结果；同一 Record 同一版本、正文相同的重复提交返回首次的结果，不产生第二条
- [ ] 版本号不连续的提交被接受
- [ ] 没有令牌、令牌无效、请求体不符合 schema、请求体里带 tenant_id 的请求都被拒绝，错误符合统一错误结构
- [ ] contracts 的语义规则 SR-01 至 SR-06 在网关侧生效，对应的无效样本全部被拒绝
- [ ] 测试把网关当黑盒：启动真实进程和真实数据库，只通过 HTTP 和 MCP 端点交互；请求与响应用 contracts 里的 schema 校验。
