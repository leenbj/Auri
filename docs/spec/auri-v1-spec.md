# Auri V1 规格

状态：ready-for-agent。写于 2026-11-15。

本规格是 PRD（需求基线 1.3 版）、`GLOSSARY.md`、ADR-002 至 ADR-0020 和已冻结的数据合同 1.0 的综合，供拆分工单使用。出现冲突时的优先顺序是：ADR、数据合同、术语表、PRD、本规格。用词以术语表为准。

## Problem Statement

用户在走路、做家务、开车这类腾不出手的时候想到一件事，想马上口述下来，并且让自己电脑上的 Agent 之后能读到这段话。现有的办法都要掏出手机、解锁、打开应用、点录音，录完还要手动把文字搬到 Agent 那里。

用户戴着蓝牙耳机（首先是 HUAWEI FreeClip 2 和 FreeClip），希望只靠耳机上的手势完成“开始说、说完停”。用户不愿意让口述的音频和文字经过任何第三方服务：音频不出手机，文字只到自己的电脑。

现成的开源应用没有一个同时满足这些条件。它们或者只在桌面运行，或者在蓝牙麦克风不可用时悄悄改用手机麦克风，或者把静音当成停止，或者要求文字经过云端。

## Solution

Auri 是鸿蒙 NEXT、iOS、Android 三端的原生应用，加一个装在用户自己电脑上的 Gateway。

用户开启 Control Mode 后，用耳机手势开始一次 Capture Session。应用确认音频确实来自所选耳机的麦克风之后才开始保存，任何情况下都不改用手机麦克风。用户说话时停顿多久都不会结束录音；没人说话的片段被丢弃，不占空间。用户再做一次手势（iOS 上是音量手势或屏幕按钮）结束录音。

录音结束后，手机用内置模型把语音转成文字，产生一条 Record 和它的第一个 Revision。音频留在手机上。

文字按用户为每个 Destination 选定的方式发送：自动发送，或预览确认后发送。手机在家里的局域网内时，文字直接送到 Gateway；在外面时先在手机上排队，回到局域网后自动补传。

用户电脑上的 Agent（验收对象是 Hermes 和 Claude Code）通过 MCP 连接 Gateway，领取发给自己的文字，处理后确认。每个 Agent 只能读到发给它的内容，各自的确认状态互不影响。

用户可以在手机上改字，每次保存产生一个新的 Revision，旧版本保留。用户可以删除整条 Record，删除后不会因为补传而复活。

各平台做不到的事如实标明，不用变通手段绕过。已知的是：iOS 录音中收不到耳机按键，冷启动后也不能只靠耳机手势开始录音。

## User Stories

### 首次设置

1. As a 用户, I want 在应用里选择用哪副蓝牙耳机录音, so that 应用知道该确认哪个输入来源。
2. As a 用户, I want 一个校准向导带我依次测试“不录音时的手势”“录音中的手势”“停止后再次开始”“锁屏时”, so that 我知道这副耳机在这台手机上哪些场景能用。
3. As a 用户, I want 校准结束后看到一份逐项的能力报告, so that 我不会误以为“已连接”就等于“都能用”。
4. As a 用户, I want 没测过的场景显示为“未测试”而不是“支持”, so that 我不会在关键时刻才发现不行。
5. As a 用户, I want 耳机的固件版本或左右耳信息拿不到时显示“系统未提供”, so that 应用不会给我猜出来的信息。
6. As a 用户, I want 应用只申请它真正用到的权限并说明用途, so that 我清楚它能做什么。
7. As a 用户, I want 在手机上下载转录模型时能看到大小、所需空间和许可证, so that 我在下载前知道代价。
8. As a 用户, I want 模型下载可以暂停和恢复，并在校验通过后才启用, so that 损坏的模型不会被加载。
9. As a 用户, I want 在电脑上用一条命令启动 Gateway 并得到一个配对二维码, so that 我不用配置域名或证书。
10. As a 用户, I want 用手机扫码完成配对, so that 我不用手动输入地址和密钥。
11. As a 用户, I want 配对码只能用一次而且很快过期, so that 别人捡到截图也配不上。
12. As a 用户, I want 在手机上创建 Destination 并为它生成 Agent 用的凭证, so that 每接一个 Agent 不用登录电脑。
13. As a 用户, I want 创建 Destination 时必须选“自动发送”或“预览确认”，没有默认值, so that 授权是我自己明确作出的。
14. As a 用户, I want 生成或轮换凭证前先通过手机的生物识别, so that 借用我已解锁手机的人拿不到凭证。
15. As a 用户, I want 凭证只显示一次, so that 它不会留在界面上被人看到。

### 录音

16. As a 用户, I want 开启 Control Mode 后用耳机手势开始录音, so that 我不用碰手机。
17. As a 用户, I want 没开 Control Mode 时耳机手势不会触发录音, so that 平时听歌不会误录。
18. As a 用户, I want 应用确认音频确实来自耳机麦克风之后才开始保存, so that 录下的不是手机麦克风的声音。
19. As a 用户, I want 耳机麦克风不可用时应用拒绝录音并告诉我原因, so that 它不会悄悄改用手机麦克风。
20. As a 用户, I want 说话时停顿很久也不会结束录音, so that 我可以边想边说。
21. As a 用户, I want 没人说话的片段被自动丢弃, so that 录音文件里只有有用的内容。
22. As a 用户, I want 知道两句话之间实际隔了多久, so that 回看时能还原当时的节奏。
23. As a 用户, I want 在 Android 和鸿蒙上再做一次耳机手势就停止录音, so that 开始和结束用同一个动作。
24. As a iOS 用户, I want 录音中用音量手势或屏幕按钮停止, so that 在耳机按键收不到的情况下仍能结束录音。
25. As a 用户, I want 开始、停止、启动失败各有不同的提示音或震动, so that 不看屏幕也知道发生了什么。
26. As a 用户, I want 录音到达我设定的时长上限时自动停止并保存, so that 忘了停也不会一直录下去。
27. As a 用户, I want 到上限前一分钟得到提示, so that 我来得及收尾。
28. As a 用户, I want 录音中耳机断开时已录的部分被保存并标为“被截断”, so that 内容不丢，我也知道它不完整。
29. As a 用户, I want 来电打断录音后不会自动续录, so that 通话内容不会被录进去。
30. As a 用户, I want 应用被系统杀掉后，重新打开能找回已录的片段, so that 意外不会让整段丢失。
31. As a 用户, I want 应用重新打开后不会自己开始录音, so that 麦克风只在我发出命令时打开。
32. As a 用户, I want 一次手势没录到任何人声时仍然留下一条“无语音”的 Record, so that 我能分清“手势没生效”和“生效了但没录到话”。
33. As a 用户, I want 在准备阶段再做一次手势就取消, so that 误触可以立刻撤回。
34. As a 用户, I want 录音受阻后只有我再次发出开始命令时才重试, so that 应用不会自己反复尝试开麦。
35. As a 用户, I want 首页分开显示耳机连接状态、实际麦克风来源、耳机控制是否可用、当前录音状态, so that 一个“已连接”不会掩盖其他问题。
36. As a 用户, I want 屏幕上始终有手动开始和停止按钮, so that 耳机手势不可用时有兜底。
37. As a 用户, I want 系统的麦克风指示始终可见, so that 我确信没有被偷录。

### 转录

38. As a 用户, I want 录音停止后自动在手机上转成文字, so that 我不用手动触发。
39. As a 用户, I want 音频始终留在手机上, so that 我的声音不会被上传到任何地方。
40. As a 用户, I want 没有模型或手机过热时转录等待而不是失败, so that 条件恢复后它能继续。
41. As a 用户, I want 转录进行时仍能开始新的录音且不掉帧, so that 连续口述不受影响。
42. As a 用户, I want 对同一段录音重新转录时产生新的 Revision、保留旧的, so that 我可以比较结果。
43. As a 用户, I want 每个 Revision 写明是哪个模型转出来的, so that 我能判断它的可靠程度。
44. As a 用户, I want 转录没有识别出语音时得到明确说明而不是一段编造的文字, so that 记录是可信的。
45. As a 用户, I want 普通话和中文夹英文都能较准确地识别, so that 我平时说话的方式就能用。

### 文字与发送

46. As a 用户, I want 在手机上修改转录文字, so that 识别错的地方可以改正。
47. As a 用户, I want 每次保存产生新的 Revision 而旧的保留, so that 改错了还能回看原文。
48. As a 用户, I want 选了“自动发送”的 Destination 在转录完成后立即收到初稿, so that 我完全不用碰手机。
49. As a 用户, I want 自动发送的初稿被标为“未审核”, so that Agent 知道它没经我看过。
50. As a 用户, I want 选了“预览确认”的 Destination 只在我确认后才收到, so that 敏感内容由我把关。
51. As a 用户, I want 改字后的新 Revision 不会自动重发给已经收到旧版本的 Agent, so that Agent 不会把同一件事做两遍。
52. As a 用户, I want 我确认重发时，Agent 还没领取的旧版本被自动取消, so that Agent 只看到最新的。
53. As a 用户, I want 给每条内容标上“备忘”或“请求执行”, so that Agent 知道我的意图。
54. As a 用户, I want 看到每个 Destination 对每条 Record 的状态：已入库、已领取、已确认, so that 我知道文字到了哪一步。
55. As a 用户, I want 界面不把“已确认”说成“已处理”, so that 我不会高估 Agent 做了什么。
56. As a 用户, I want 按时间、关键词、发送状态筛选 Record, so that 能找到以前的口述。
57. As a 用户, I want 把 Record 导出为 TXT 或 Markdown, so that 可以在别处使用。

### 同步

58. As a 用户, I want 在家里的局域网内时文字直接送到我的电脑, so that Agent 很快就能读到。
59. As a 用户, I want 在外面时文字在手机上排队并显示“等待回到局域网”, so that 我知道它没丢也没失败。
60. As a 用户, I want 回到局域网后自动补传, so that 我不用手动操作。
61. As a 用户, I want 补传不会产生重复的 Record, so that 网络不稳时结果仍然正确。
62. As a 用户, I want 电脑的 IP 变了之后手机能自己重新找到 Gateway, so that 我不用重新配对。
63. As a 用户, I want 手机发现 Gateway 的公钥和配对时不一样就拒绝连接并提示我, so that 局域网里的其他设备冒充不了我的电脑。
64. As a 用户, I want Gateway 的证书续期后不用重新配对, so that 日常维护不打扰我。
65. As a 用户, I want 需要我处理的同步问题（重新配对、重新授权）和会自动恢复的问题显示得不一样, so that 我知道什么时候该动手。

### 删除与隐私

66. As a 用户, I want 单独删除一条 Record 的音频而保留文字, so that 可以释放空间。
67. As a 用户, I want 设置音频在转录成功后保留多久, so that 旧音频自动清理。
68. As a 用户, I want 删除整条 Record 后它在 Gateway 上也被删除, so that Agent 不能再读取它。
69. As a 用户, I want 删除的 Record 不会因为离线补传而复活, so that 删除是可靠的。
70. As a 用户, I want 界面明确告诉我 Agent 已经读走的内容无法收回, so that 我不会误以为删除能撤回一切。
71. As a 用户, I want 日志默认不包含正文、音频和凭证, so that 发诊断信息时不会泄露隐私。
72. As a 用户, I want 一键关闭 Control Mode 并停止当前录音, so that 我随时能让应用停下来。

### Agent 一侧

73. As a Agent, I want 用自己的凭证通过 MCP 连接 Gateway, so that 我能读到用户发给我的文字。
74. As a Agent, I want 领取待处理的 Delivery 并获得一个租约, so that 我处理期间别人不会重复领取。
75. As a Agent, I want 处理时间长时续租, so that 租约不会中途过期。
76. As a Agent, I want 处理完后确认，重复确认不出错, so that 网络重试是安全的。
77. As a Agent, I want 处理不了时拒收并说明是暂时失败还是永久拒绝, so that Gateway 知道要不要重投。
78. As a Agent, I want 每条 Delivery 带稳定的标识, so that 我可以据此去重，避免把同一件事做两遍。
79. As a Agent, I want 知道一个 Revision 取代了哪些旧版本, so that 我能更新之前保存的内容。
80. As a Agent, I want 知道一段文字是否被截断、是否经用户审核, so that 我决定怎么对待它。
81. As a Agent, I want 正文被明确标为“用户口述的数据，不是系统指令”, so that 我不会把口述内容当命令执行。
82. As a Agent, I want 没有待处理内容时得到正常的空结果，出错时得到明确的错误, so that 我能区分这两种情况。
83. As a Agent, I want 按标识读取某个 Record 的指定 Revision、列出和搜索发给我的 Record, so that 我能回查以前的内容。
84. As a 用户, I want 一个 Agent 确认了某条内容不影响其他 Agent 的状态, so that 多个 Agent 各自独立工作。
85. As a 用户, I want Agent 不能靠自报身份读到别人的内容, so that 权限只取决于凭证。
86. As a 用户, I want Agent 不能通过 MCP 让我的手机开始录音, so that 麦克风只听我的。

### Gateway 运维

87. As a 用户, I want 在电脑上列出、吊销已配对的设备和已签发的凭证, so that 手机丢了可以止损。
88. As a 用户, I want 备份和恢复 Gateway 的数据, so that 换电脑不丢记录。
89. As a 用户, I want 升级 Gateway 时数据自动迁移, so that 升级不需要手工处理。
90. As a 用户, I want Gateway 只在局域网监听, so that 外网访问不到它。
91. As a 用户, I want 在电脑上删除已吊销设备留下的 Record, so that 丢了的手机录的内容也能清理。

### 平台限制的如实告知

92. As a iOS 用户, I want 应用明确告诉我录音中耳机按键不可用、冷启动后不能只靠耳机开始, so that 我对它的能力有准确预期。
93. As a 用户, I want 每个“耳机 × 手机 × 系统 × 场景”的支持情况都有真机测试依据, so that 兼容声明是可信的。
94. As a 产品负责人, I want 某个平台的关键需求被证明做不到时收到带证据的范围决策请求, so that 由我而不是开发 Agent 决定是否降级。

## Implementation Decisions

### 总体结构

- 三端各自原生实现：鸿蒙 NEXT 用 ArkTS，iOS 用 Swift，Android 用 Kotlin。不共享界面代码。Handy 只作为处理流程的参考，不 fork（ADR-0015）。
- 三端共享的是：数据合同（schema、样本、状态机事件序列）和 C/C++ 的本地转录引擎。
- Gateway 用 Python 和官方 MCP SDK，SQLite 持久化，单用户自托管（ADR-008、ADR-0013）。
- 手机不作为 MCP Server，V1 不做手机直连 Agent（ADR-0018）。
- 所有 SDK、MCP 版本、模型（含哈希与许可证）固定版本，不追踪上游主干。

### 手机端的模块

每个平台按同样的职责划分，模块之间只通过合同里定义的类型交互：

- **控制适配器**：把平台的媒体事件、音量变化、屏幕按钮归一化成带来源、序号和单调时间的控制事件。只选一个主事件源或做去重。来源不可验证时记为未知，不猜左右耳。
- **采集适配器**：检查权限与生命周期；请求蓝牙输入；用系统观测到的实际路由生成 Route Evidence；在路由确认前把帧放进 Quarantine；路由变化时立即关闸。
- **采集协调器**：实现采集状态机。命令串行处理，每个 Capture Session 带会话标识、代次和路由纪元，旧回调不能改写新会话。这是手机端最重要的深模块，接口小（接收控制事件和路由事件，产出录音结果），内部处理全部竞态。
- **录音存储**：分段写入，可在崩溃后恢复；封存时生成内容哈希；VAD 丢弃的静音不落盘，但保留各语音片段在原始时间线上的位置（ADR-0016）。
- **转录**：统一的引擎接口；本地引擎；模型清单、下载、校验与原子启用；调度器保证转录不阻塞新录音，默认并发为 1。
- **记录库**：Record 与不可变的 Revision 链；发布与创建待同步任务在同一个本地事务里完成；删除墓碑。
- **同步**：实现同步状态机；先连配对时记下的地址，连不上用 mDNS 查找；每次连接核对 Gateway 公钥指纹；区分“等待网关”“稍后重试”“需要用户处理”。
- **界面**：首页、记录库与详情、耳机设置与校准、转录设置、Agent 连接页、隐私与诊断页。只显示真实状态。

### Gateway 的模块

- **认证**：设备令牌与 Destination 凭证分离；库内只存哈希；Tenant 只由认证结果映射得出；请求体里的身份字段一律不接受。
- **配对与设备管理**：命令行生成一次性配对码和配对载荷；命令行可列出、吊销设备与凭证，可删除已吊销设备的 Record。
- **入库**：幂等提交 Revision；只比较正文哈希判定重复；只有来源设备能写（ADR-0020）；接受不连续的版本号；删除墓碑阻止复活。
- **投递**：每个 Revision 对每个 Destination 一条 Delivery；租约式领取、续租、确认、拒收；新版本发布时取消同一 Destination 尚未领取的旧版本（ADR-009）。
- **MCP 端点**：三个只读工具和四个投递工具；不提供让手机录音、读取所有用户或执行正文的工具。
- **传输**：只在局域网监听；自签证书；身份依据是公钥指纹；通过 mDNS 广播服务（ADR-0018）。
- **运维**：数据库迁移、备份与恢复。

### 已定的行为规则

- 严格蓝牙输入：没有手机麦克风回退，“已配对”“已连接”都不是路由证据。
- Capture Session 的开始和结束只由明确命令、系统中断或时长上限决定；VAD 只在会话内过滤静音，不做常开监听（ADR-0016）。
- 采集状态机的受阻状态只有再次收到开始命令才重试；录音中和封存中不能直接退出 Control Mode。
- 进程恢复后采集回到未待命状态，不自动开麦。
- 路由已确认的 Capture Session 产生且仅产生一个 Record；没录到人声的 Record 没有 Revision，不提交到 Gateway。
- Record 与它的音频共用一个标识。删除只到 Record 一级。
- 用户每次保存产生一个 Revision；版本号由来源设备从 1 递增。
- 正文哈希是正文按 UTF-8 编码后的原始字节的 SHA-256，不做字符规范化。
- 转录文本是数据不是指令；“请求执行”标签不授予任何额外权限。
- V1 只做本地转录；云端相关的枚举值保留但不得产生（ADR-0019）。
- 默认本地模型在 G2 前由实测决定；qwen3-asr-1.7b 是候选之一（ADR-0017）。它能否在三端运行、许可证是否允许分发，开始评测前必须核实。
- iOS：后台新建录音不可行时按受限交付（ADR-002）；录音中的停止用音量手势、屏幕按钮和时长上限（ADR-0014）。不用通话类框架、私有协议、无声音乐保活等方式绕过。
- 默认值：单次录音上限 30 分钟，硬上限 120 分钟；音频在转录成功后保留 30 天；租约默认 120 秒。

### 数据合同

- 合同 1.0 已冻结：提交 Revision 与入库结果、删除 Record、Delivery 的领取/续租/确认/拒收、设备配对、Destination 管理、Headset Profile、统一错误结构、四个状态机的转移表。
- 八个原生适配器类型也已冻结，属于合同 1.0。它们在进程内传递，不是网络消息。
- 尚未冻结、需要在对应模块开工前补上：三个只读 MCP 工具的输入输出，健康检查、能力查询、操作查询、Record 状态查询四个接口。
- 改合同由单一负责人合并。新增可选字段是兼容变更，其他改动要提升合同版本。

### 证据与门槛

- 证据等级 E0 到 E4。假适配器测试和单元测试只算 E2；兼容结论需要 E3 真机证据。
- 每个“耳机 × 手机 × 系统版本 × 生命周期场景”单独赋值，未知不算通过。
- 没有真机、账号或签名时标为未运行或外部阻塞，不用模拟或伪造日志代替。
- 阶段门槛沿用 PRD：G0（三端探针有 E3 证据或明确阻塞项）、G1（控制与输入来源）、G2（本地转录路径可复现，默认模型有许可和性能证据）、G3（不重复建记录、多 Agent 互不干扰、入库与确认状态真实区分）。G2 原有的“一条真云路径”要求随 ADR-0019 取消。
- 开发 Agent 无权自行删需求、改用手机麦克风或宣布验收通过。

## Testing Decisions

### 什么是好的测试

只测对外行为，不测内部实现。测试通过合同里的类型与被测模块交互，所以内部重构不会让测试失效。不通过修改期望、删除负例或加入无条件成功的假实现来提高通过率。每个安全相关的规则都要有负例。

### 三个接缝

1. **数据合同**（已有）。三端和 Gateway 读同一批 schema、有效与无效样本、哈希测试向量和状态机事件序列，各自比对。现有的合同测试是先例：它检查无效样本是否因为声明的那个原因被拒绝，并要求每条状态机规则至少被一个样本覆盖。
2. **Gateway 的对外接口**。把 Gateway 当黑盒：启动真实进程和真实数据库，从 HTTP 提交，从 MCP 端点领取和确认。覆盖：重复提交不产生重复记录；正文不同报冲突；非来源设备被拒绝；删除后不复活；并发领取只有一方成功；租约过期后确认被拒绝；新版本取消未领取的旧版本；一个 Destination 的凭证读不到另一个的内容；请求体里自报身份无效；公钥不符时客户端拒绝连接。
3. **手机端的原生适配器接口**。每个平台的采集协调器、转录调度、记录库和同步只通过适配器接口接触系统。测试时换成假适配器，喂入控制事件和路由事件，检查状态和产出的录音结果。状态机事件序列样本直接作为测试输入。必须覆盖：取消后迟到的回调、旧代次的写入、路由纪元失配、封存中的过时切换命令。

### 不属于自动化测试的验收

- **真机证据**：三端探针和校准流程在真实的耳机和手机上运行，按 PRD 的测试用例清单逐项记录。必测“蓝牙麦克风已激活后再次手势能否停止”。
- **转录评测**：候选模型在三台目标手机上用同一批耳机录制的中文音频测识别质量、内存峰值、冷启动、耗时和发热。语料要包含轻声、远讲和噪声样本，用来检验 VAD 是否误丢。
- **端到端验收**：手机在局域网内把文字送到 Gateway，Hermes 和 Claude Code 各自通过 MCP 读到并确认。

## Out of Scope

- 云端转录，包括云端提供商适配、转录代理服务、音频上传授权（ADR-0019）。
- 手机直接作为 MCP Server；在局域网外同步；把 Gateway 暴露到公网或接入 VPN、隧道服务（ADR-0018）。
- 多用户管理、注册登录、OAuth；团队共享的 Tenant（ADR-0013）。
- 多台设备编辑同一个 Record；设备迁移继承写权限（ADR-0020）。
- 只删除某一个 Revision。
- 实时字幕、流式转录。
- 向 Agent 主动通知的事件分发器（PRD 列为可选，V1 不做，Agent 靠轮询领取）。
- 跨平台界面框架。
- 应用商店上架。V1 到开发者签名与测试分发为止。
- 靠 VAD 或静音结束录音；常开监听；任何形式的手机麦克风回退。
- iOS 上用通话类框架、私有蓝牙协议或保活手段恢复耳机按键。
