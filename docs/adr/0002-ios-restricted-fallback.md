# ADR-002：iOS 后台新建录音不可行时，以 PARTIAL 受限版本交付

PRD 第 1.4 节指出 iOS 公开 API 限制后台新建录音，P0 之前无法确定“应用休眠或被终止后，仅靠耳机手势开始新录音”是否可行。产品负责人预先决定：若 P0 以 E3 真机证据证明该场景不可行，iOS 作为受限版本交付，该场景在支持矩阵中标 `PARTIAL`，不写成完整支持。受限版本至少保证应用在前台时耳机手势可开始与停止录音；录音已在进行时（含锁屏、后台）能否继续并由耳机停止，按场景逐项以 P0 实测定级。

无论 P0 结果如何，录音输入只能是蓝牙耳机麦克风（`bluetooth_only`），任何情况下都不引入手机麦克风回退。若 iOS 连受限版本的严格蓝牙输入也做不到，按 BLOCKER 处理，另行提交范围决策。

## Considered Options

- **手机麦克风回退**：否决，违反 U-004 与 FR-REC-001。
- **从 V1 删除 iOS**：否决，三端是 U-001 的基线要求；降级交付仍保留 iOS 的前台价值。
- **P0 失败后再停下来等决策**：否决，iOS 结论越早越好，预授权让探针结果出来后可直接按此路径推进。

## Consequences

- 本 ADR 只预授权“降级交付”这一条路径。开发 Agent 仍无权自行宣布验收通过、改用手机麦克风或删除需求；`PARTIAL` 必须附 E3 证据。
- P0 的 iOS 探针必须逐场景分别记录：前台开始/停止、已在录音时锁屏、后台停止后再次开始、进程终止后开始。
- 文件编号沿用 PRD 第 28 章的 ADR 编号（本文件是 ADR-002）；PRD 之外的新决策从 0013 起编。
