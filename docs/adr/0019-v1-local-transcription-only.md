# ADR-0019：V1 只做本地转录，云端转录推迟

PRD 把本地转录和云端转录都列为 V1 必须具备的能力，并在 ADR-006 里选定阿里云为首个云端提供商。产品负责人现在把隐私和手机内置模型放在首位，决定：V1 只交付本地转录，音频不出手机；云端转录不在 V1 实现。数据合同里保留区分转录位置的字段（`execution_location` 等），以后加云端时不用改数据结构。

## Considered Options

- **按 PRD 原计划 V1 同时做本地和云端**：否决。云端要做上传授权、预算、提供商适配和代理服务，与当前“数据不出手机和自己的电脑”的目标无关，还占用 P2 的工期。
- **连合同字段也删掉**：否决。Revision 的来源信息里本来就要记录转录引擎和运行位置，删掉字段以后再加是合同的不兼容变更。

## Consequences

- DEV-011（云 ASR 接口与首个提供商）和 DEV-012（第二提供商）推迟到 V1 之后；`services/asr-proxy` 暂不开工；网关的 `/v1/asr/jobs` 三个接口 V1 不实现。
- PRD 第 5 章“V1 必须具备……至少一家云端转录服务”改为 V1 之后的目标；FR-ASR-002 的四种模式中，V1 只实现“仅本地”和本地引擎之间的“手动重转录”。
- ADR-006 的选型结论保留，但决定时间从“G2 前”改为“启动云端转录时”。
- 本地转录失败时没有云端可回退，应用要给出具体原因（缺模型、内存不足、热保护），并允许稍后重试，符合 FR-ASR-004。
- 依赖云端转录的测试用例在 V1 的验收里标为不在范围内，而不是 `NOT_RUN`，由合同负责人在测试清单里逐条标注。
