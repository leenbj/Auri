# ADR-0018：网关只在局域网提供服务，手机绑定自签证书指纹；V1 不做手机直连 MCP

本决策取代 ADR-008 中“手机经带正式 TLS 证书的公网域名访问”这一句，ADR-008 的其余内容不变。

产品负责人出于隐私考虑，希望 Agent 不经过任何第三方服务就能读到手机上的文字，并问能否让 Agent 直接连手机。结论是保留 Gateway，但把它限制在用户自己的局域网内：

- Gateway 装在运行 Agent 的那台用户自己的电脑上，只在局域网监听，不部署到云主机，不暴露到公网。
- Gateway 首次启动时自己生成 TLS 证书。配对码仍由网关命令行生成，同时携带网关地址和证书指纹（可显示为二维码）。手机配对时记住这个指纹，之后只信任这一张证书。
- 手机不在该局域网时，已发布的 Revision 留在手机本地排队，回到局域网后自动补传。不为了在外同步而接入 VPN 或隧道服务。
- V1 不做“手机直接当 MCP Server”的模式。

## Considered Options

- **手机直接当 MCP Server**：否决。iOS 应用锁屏或切到后台后几秒内被挂起，连接断开；Android 要靠前台服务维持，仍可能被厂商省电策略杀掉；鸿蒙 NEXT 需要长时任务，限制未实测。手机在蜂窝网络下没有可访问的固定地址，要跨网络只能借助隧道服务，那才是引入第三方。实际效果是只有应用在前台且与电脑同一 Wi-Fi 时 Agent 才能读到。此外三端要各写一套 MCP 服务端和凭证管理，并绕过 Gateway 的授权、幂等与租约。
- **保持 ADR-008 原方案（公网域名 + 正式证书）**：否决，产品负责人不希望文字经过公网上的任何节点。
- **局域网内用不加密的 HTTP**：否决，同一 Wi-Fi 下的其他设备能截获文字和设备令牌。
- **经 VPN 或隧道服务在外同步**：否决，引入了外部服务；产品负责人接受“在外录的内容回家后才能被 Agent 读到”。

## Consequences

- 数据只存在于用户的手机和用户的电脑上。Gateway 不是第三方服务，这一点要在产品说明里写清楚。
- 在外录音的文字要等手机回到局域网才能入库，Agent 在此之前读不到。界面要能显示“等待回到局域网”的排队状态，不能显示成发送失败。
- 证书指纹绑定不是跳过证书校验：手机必须校验指纹，指纹不符就拒绝连接，不提供“忽略并继续”。PRD 第 20 章“不能把跳过证书校验作为解决连接错误的正式方法”仍然成立。
- Gateway 重新生成证书或更换电脑后，手机需要重新配对。证书的有效期和轮换流程在 DEV-015 里设计。
- 电脑的局域网 IP 可能变化。手机如何重新找到 Gateway（固定 IP、主机名或局域网发现）在 DEV-002 的合同里确定；无论用哪种方式，证书指纹都是身份依据，地址不是。
- iOS 访问局域网需要用户授予“本地网络”权限，被拒绝时要给出明确提示。
- Agent 与 Gateway 在同一台电脑时可以走本机回环地址；Agent 在局域网内另一台机器时，同样要校验这张证书。Hermes 和 Claude Code 对自签证书的配置方式在 ADR-007 的宿主联调里核实。
- PRD FR-MCP-002 中“远程 HTTPS MCP”一行在 V1 的含义改为局域网内的 HTTPS，由本 ADR 约束。
- 日后若要做手机直连或在外同步，另写 ADR 评估。
