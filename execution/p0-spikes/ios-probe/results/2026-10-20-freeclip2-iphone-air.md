# DEV-004 结果：iPhone Air × HUAWEI FreeClip 2（前台）

记录日期：2026-10-20。证据等级 E3（真机）。原始日志在本机 `results/raw/`，因含设备名与真实音频不入库；本文只写脱敏后的结论与计数。

## 测试组合

| 项 | 值 |
|---|---|
| 手机 | iPhone Air（`iPhone18,4`），iOS 26.7.1（23H30） |
| 耳机 | HUAWEI FreeClip 2；固件版本：系统未提供 |
| 被测 App | AuriProbeIOS 0.0.1（`app.auri.probe.ios`），免费账号签名 |
| 生命周期 | 仅前台、亮屏。锁屏、后台、进程终止场景**尚未测试** |
| 耳机侧手势设置 | 出厂双击为播放/暂停（音乐 App 对照确认：双击可暂停与恢复）；其余手势选项未核对 |

## 结果

| 场景 | 状态 | 证据 |
|---|---|---|
| S1 前台待命、不录音，双击 | `SUPPORTED_FOREGROUND` | 双击 → `remote_command(play)` 共 5 次到达（4 次启动实例中的 3 个，均为不录音时）；同一次还触发旧通道 `remoteControlReceived`（`subtype 100`，遥控播放） |
| S1 前台待命、不录音，三击 | 未收到命令 | 仅 1 次已标记的三击，前后无任何事件；样本太少，只能说“未观察到”，不能说该手势不可用 |
| S2 前台开始录音（用手动按钮触发，不是手势触发） | 路由证据通过 | 可用输入含手机麦克风与 `BluetoothHFP`；设置首选输入后，路由输入只剩 `BluetoothHFP`；16 kHz 单声道；丢弃帧 0 |
| **S3 录音中再次双击停止（必测）** | **`UNSUPPORTED`（本组合、已测配置）** | 见下 |
| S7 路由丢失保护 | 意外覆盖到一次 | 一次 `route_change(reason=override)` 把输入切到手机麦克风，探针在同一秒关闸并停止，接受帧 0，没有保留任何手机麦克风音频 |
| S4 / S5 / S6 / S8 | `NOT_TESTED` | 锁屏、后台再启动、进程终止未做；S8 的 Now Playing 对照已在 S3 配置里覆盖 |

### S3 详情

录音中（`BluetoothHFP` 输入）共 8 次完整录音（另有 1 次被系统路由覆盖而中止）。其中 5 次带手势标记，累计 **10 次标记双击、11 次标记三击**；另外 3 次完整录音的手势没有标记，不计入。所有录音期间**没有任何 `remote_command`，也没有任何旧通道事件**。

已测配置：

| 变量 | 取值 |
|---|---|
| 会话类别与选项 | `playAndRecord` + `allowBluetoothHFP` |
| 会话模式 | `default`、`voiceChat`、`spokenAudio` |
| Now Playing 元数据 | `off`、`paused`、`playing`（只发布元数据，没有播放任何音频） |
| 事件通道 | `MPRemoteCommandCenter` 与旧式 `remoteControlReceived` 同时监听 |

合法对照：同一个 App、同一次启动、同一副耳机，**不录音时**双击立刻到达（4 次，且在录音前后都复现）。耳机自身对双击有“滴”提示音，说明耳机识别到了手势，只是系统没有把它作为命令交给 App。

## 结论与边界

- 结论只对“已测配置”成立：iPhone Air + FreeClip 2 + 前台 + 上表的会话配置下，录音中无法用双击或三击停止。
- 没有证明的事：长按、音量类手势、其他耳机、锁屏/后台下的行为，都没测。
- 这是 U-003（同一手势完成“开始—停止”闭环）在 iOS × FreeClip 2 上的 **BLOCKER-001**，属于范围决策，开发 Agent 无权自行处理。ADR-002 预授权的是“后台新建录音不可行”的降级，**不覆盖**本问题。

## 补充：音量通道（滑动手势）

耳机映射：双击=播放/暂停，三击=无，长按=无，滑动=音量。

| 观察 | 证据 |
|---|---|
| 录音中滑动耳机柄 → `AVAudioSession.outputVolume` KVO 事件到达 | 方向可由 `delta` 正负判断 |
| 锁屏/后台时录音继续，音量事件仍到达 | 锁屏后 7 个事件 |
| 不录音（会话未激活）时无音量事件 | 对照 |
| 边界：音量到顶后再上滑只有 1 个 `delta=0` 事件；到底（0.05）后再下滑无事件 | “任意音量变化即停止”在底部会失灵，手势语法需另设计（如“上滑后下滑”的组合，或到边界时由 App 先把音量拨回中间） |

状态：音量通道在 FreeClip 2 × iPhone Air × iOS 26.7.1 上为 E3 观察到；尚未做成停止手势，也未测其他耳机。这条通道不属于“双击停止”，是否采用属于 BLOCKER-001 的范围决策。

## 补充：BLE 通道（只读探索）

- FreeClip 2 虽广播 `connectable=false`，仍可被 CoreBluetooth 直接连接（无配对弹窗），暴露 3 个服务：`FD21`、`C574EDB3-…`、`710D096D-…`，均有可通知特征；连上后推送 `5a` 开头的华为私有协议帧。
- **受控对照实验（2026-10-20，40 余次手势）无效**：三次连接都在约 5 秒后被耳机断开（`The specified device has disconnected from us.`，间隔 5.4/5.5/5.6 秒），断开后探针没有重连；绝大多数手势发生在断开之后。仅有 1 个短帧（`2b36…`）落在手势前后，无法区分是手势还是普通状态上报。
- 状态：**`NOT_TESTED`（未得结论）**。耳机在几秒内主动断开，推测在等待应用层握手；只读探针不写入，要继续就必须向华为私有协议写入握手数据，这已不是“只读探索”，且依赖未公开协议、与固件绑定、OpenFreebuds 为 GPL-3.0 只能参考事实。**未经范围决策不继续。**

## 补充：长按的路由副作用（偶然发现）

不录音时，长按阶段后半段出现 4 组 `route_change`（reason 3，`categoryChange`）：输出在 `BluetoothA2DPOutput` ↔ `BluetoothHFP` 之间往返，每次切到 HFP 后约 1.2–1.5 秒出现一次“长按了”标记，约 7 秒后切回 A2DP。推测长按触发了系统语音助手并打开 SCO 链路（耳机里该手势在华为 AI 生活中为“无”）。样本小（4 次且前 8 次长按无此现象），**不作结论**；而且录音中路由本来就是 HFP，不会再有这个变化，对“录音中停止”没有用处。

## 补充：三击映射为上一首/下一首（左耳上一首、右耳下一首）

耳机设置：左耳三击=上一首，右耳三击=下一首（华为 AI 生活）。耳机本身有效：系统音乐 App 里三击能切歌。探针 Armed，命令映射 logOnly，Now Playing 为 playing（只发布元数据）。

| 阶段 | 标记次数 | 到达的命令 |
|---|---|---|
| 本次启动内尚未激活过音频会话，不录音 | 14（两轮，含 Now Playing paused/playing） | 0 |
| **录音中（BluetoothHFP）** | 16 | **0** |
| 手动停止后立刻（会话刚用过） | 约 10 | `previousTrack`×6、`nextTrack`×3、`play`×1，同时旧通道 subtype 105/104/100 |

- 结论：三击上一首/下一首与双击一样，**录音中不送达**；停止后才送达。左右耳靠上一首/下一首区分的思路在“不录音”时可行，但对“录音中停止”无效。
- 新的限制：命令到达的前提似乎是探针最近用过音频会话；本次启动内从未录音时，不录音的三击也是 0 事件。这对“不录音时用手势开始”有影响，**需单独验证**：冷启动 + 未激活会话时，哪种手势能唤起开始。以前双击“播放”在未录音时到达过，两者差异未查清。
- 证据等级：E3，单台设备、单副耳机，次数有限。

## 补充：冷启动下耳机手势能否唤起 App

条件：`devicectl --terminate-existing` 全新启动，Armed，logOnly，Now Playing off，前台，本次启动内从未录音（未激活过本 App 的音频会话），音乐类 App 已清后台。

| 手势 | 次数 | 到达探针的命令 |
|---|---|---|
| 双击 | 11 | 0 |
| 左/右耳三击 | 13 | 0 |

- 用户观察：**每次手势都启动了系统音乐 App**，即媒体键被交给了系统默认播放 App，而不是探针。
- 锁屏部分（双击/左右三击各约 3 次）无法打标记，日志中也无 `remote_command`，视为 0 事件，但未做时间对照，证据较弱。
- 结论：本 App 不是“正在播放”App 时，耳机手势不会唤起它。命令只在 App 刚用过音频会话（刚结束录音）后送达，持续多久未测。
- 证据等级：E3，单台设备、单副耳机。

## 范围决策（2026-10-20）

BLOCKER-001 已由产品负责人决策，见 `docs/adr/0014-ios-stop-via-volume-gesture.md`：iOS 接受“录音中无法用耳机按键停止”，改用音量手势、屏幕按钮、时长上限；长按（仅“无”/“唤起语音助手”）、BLE 私有协议、通话类框架均不采用。
